# 云开发、主机部署与 Docker

## 独立云开发

本仓库可在无真实账号的独立 Codex 云环境完成开发：`npm ci --ignore-scripts && npm run check`。npm 默认缓存不可写时用 `npm ci --cache /tmp/npm-cache --ignore-scripts`。不需要用户电脑、SSH、微信扫码或模型 Token。依赖由 lockfile 锁定，不装全局工具。

GitHub Actions 仅一个 Node 24 作业，执行 lint、类型检查、测试、编译；10 分钟超时，旧运行可取消，权限仅 `contents: read`，不读取业务 secrets，不发布镜像，不部署生产。没有高成本矩阵。CodeRabbit 仅依赖仓库已有授权，不自动安装应用或新增权限。

## 主机部署

推荐 Node 24。以独立非 root 系统账号运行，配置、凭据只读，只有 `stateDir` 可写。按 README 安全配置后执行 `npm run login`，此命令需要用户交互扫码，不能在 CI 做。后台运行用系统服务管理器，设置工作目录、运行用户和自动重启。应用收到 SIGINT/SIGTERM 后停止接收、等待当前有界请求并关闭 Socket/数据库；服务管理器应给至少 300 秒退出宽限。

健康命令：`node dist/src/main.js health`。仅检查最近轮询与工作循环及 Socket 活跃状态，不代表每条消息成功。状态数据库的 `jobs.status` 可区分失败、待重试和结果不确定；不要把包含 payload 的查询输出贴到公开 issue。

## Docker

```bash
docker build -t wechat-slack-bridge:local .
```

容器固定 UID/GID 1000，默认只写 `/app/state`。安全准备三个挂载：配置 `/app/config.local.json`，凭据 `/run/secrets/slack.json`，状态 `/app/state`。配置对应填写 `secretFile: /run/secrets/slack.json`、`stateDir: /app/state`。在部署主机创建状态目录并给予 UID 1000 所有权和 0700 权限；凭据文件同样由 UID 1000 读取、0600/0400，不能使用默认全员可读的 secret 文件模式。

示例使用当前目录中用户已配置的文件，不包含真实凭据：

```bash
docker run --rm -it --read-only --cap-drop ALL --security-opt no-new-privileges \
  -v "$PWD/config.local.json:/app/config.local.json:ro" \
  -v "$PWD/secrets/slack.json:/run/secrets/slack.json:ro" \
  -v "$PWD/state:/app/state" \
  wechat-slack-bridge:local node dist/src/main.js login

docker run -d --name wechat-slack-bridge --restart unless-stopped \
  --stop-timeout 300 --read-only --cap-drop ALL --security-opt no-new-privileges \
  --memory 256m --cpus 0.5 \
  -v "$PWD/config.local.json:/app/config.local.json:ro" \
  -v "$PWD/secrets/slack.json:/run/secrets/slack.json:ro" \
  -v "$PWD/state:/app/state" \
  wechat-slack-bridge:local
```

不需入站端口。镜像构建白名单不包含配置、state、secrets、media、日志或 Git 历史。基础镜像跟随 Node 24 安全更新；正式部署可由用户审核后固定 digest。本项目不自动推送镜像或启动生产容器。
